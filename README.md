# Drape fitting room

Drape is an on-device virtual fitting mirror. The camera tracks one wearer and animates the selected garment from a product photo. A separate photo renderer is available on request. The preview estimates appearance. Physical sizing requires measurements.

## Run

Install locked dependencies with `npm ci` on Node 22.13 or newer and use `npm run dev`. Build the Cloudflare Worker and its browser assets with `npm run build`.

## Camera fitting and operating cost

Open the fitting room over HTTPS (or localhost). Choose **Start camera**, allow video access and step back until your head and feet are in frame. You can also run the animated studio sample without granting camera access. Select a garment or use **Add garment** to import a shop image. The live renderer works best with a front-facing, isolated product.

Body measurements run on the device. The tracker uses MediaPipe Pose Landmarker or a MoveNet worker with WASM/SIMD and a JavaScript fallback. It measures at about 4–5 times per second while still and up to 11 times per second during motion on capable hardware. Between measurements, the same joint positions drive both the garment mesh and the optional **Show body points** view. Loss of the person clears the overlay. Shirts use separate torso and sleeve panels. Each side of the waist is estimated along its own shoulder-to-hip line. Three waist pins and three hem pins follow the shirt body while cuffs follow the arms. For brief single-hip dropouts, a prior pelvis measurement guides the hidden hip for up to 420 milliseconds. Trousers follow hips, knees and ankles, and dresses use both upper and lower anchors.

Live camera video, animation, garment changes after import, and local JPEG saves make zero calls to a rendering provider. A five-second timer saves a fitted frame in IndexedDB. Saved images omit the tracing overlay. On supported browsers, versioned public model files are cached after first use. Hosting, initial asset downloads, and fetching new shop products still use network resources. There is no per-frame server or GPU job.

Set the runtime variable `DRAPE_LOCAL_ONLY=true` for a deployment that disables optional online photo rendering, even if provider credentials are present. The local path also works when no provider credentials are set.

## Garment sizes

In the camera or photo fitting room, use **Size up** or **Size down** to compare the same garment on the same body. **Reset** restores the pictured size. The renderer adjusts the chest, sleeves, waist, hips and length according to the garment type and holds the neck or waistband in place. Each garment remembers its selected size on the device. Saving a fitted frame keeps its size label. Size changes run locally.

For products with a usable finished-garment chart, the controls step through the listed sizes. **Add size chart** accepts measurements in centimetres or inches and asks which size appears in the product photo. **Compare a garment you own** compares a laid-flat width from a similar piece against comparable measurements in the chart. Missing dimensions use estimated grading. With no usable chart, the controls offer three estimated steps in each direction and cannot determine a shopper’s retail size.

Sizing up can cover an old shirt showing at the sides. An open jacket exposes its underlayer and a cropped piece can leave a longer shirt visible below the hem. The fitting guide links to [size comparisons from the local renderer](public/camera/size-comparison.jpg).

## Optional AI photo generation

With **AI photo try-on**, a visitor can choose to send one pair at a time to [WeShopAI’s official public trial](https://huggingface.co/spaces/WeShopAI/WeShopAI-Virtual-Try-On). Photos are resized and stripped of camera metadata. The browser displays both inputs and the recipient before transmitting either photo. Jobs are submitted only after explicit confirmation and are never retried automatically. Public capacity, cropping and fine details vary. The worker does not persist photos or results.

To use your own GPU, set both `DRAPE_RENDER_URL` and `DRAPE_RENDER_TOKEN` as private runtime settings. The GPU endpoint is the HTTPS origin of the authenticated renderer. Download `public/downloads/Drape-Local-AI-Studio.zip` for the open-weight FASHN VTON v1.5 backend, setup and a separate local browser interface.

To use the paid managed FASHN Try-On Max endpoint, set the private Worker secret `FASHN_API_KEY` instead. Its quality 1K setting uses the owner's provider credits. Select one private renderer per deployment. A partial custom configuration disables new jobs. Hosted jobs bind result access to the signed-in user and expire. The public route sends the photos directly to the trial provider.

## Studio samples, fitting guide and test data

The opening Oxford on Omar and the knit on Maya are saved results generated by the live trial using those exact inputs. The six other studio pairs are previously generated image edits. Selecting a fresh photo or product clears the result. The optional Fit guide is an adjustable browser-local placement tool using the garment pixels, pose landmarks and silhouette. The wardrobe and saved looks use IndexedDB.

Open **Fit tests** to inspect source person, product and result for the 100 original synthetic gallery pairs. The methods panel explains gallery generation and a separate research comparison on held-out target images. That research benchmark uses the low-resolution DM-VTON pipeline. The downloadable research code and licenses are in `public/downloads/Drape-Research-Try-On.zip`.

Choose **Test hands at waist** in the camera to replay four posed photos through your browser’s detector. Turn on **Show body points** to see the waist and hem guides; saved images contain the fitted shirt without the guides. The foreground pass samples the person’s camera pixels to keep hands visible over the fabric. A small local image sampler measures shoulder and sleeve outlines where the background has a clear boundary. Color-based compositing can still miss overlapping hands or leave original clothing visible along the edges.

The 100 on-device gallery images use 100 different synthetic person/garment pairs. For photos with a cropped or poorly observed pelvis, the photo preview labels the shoulder-based waist estimate. A live camera needs visible hips to initialize the shirt. One front product image cannot supply the texture on the back or hidden layers of clothing.

Run `node --test tests/*.test.mjs` for the tracker, garment panels, lighting, hand occlusion and local rendering regressions. Run `node scripts/verify-hand-poses.mjs` to check the four source images against the 33 manually marked hand pixels, 32 nearby fabric pixels and waist/hem positions. Run `node scripts/pose-worker/refresh-cache.mjs` to verify the hashes of the cached model assets.
